# 精细战机与科幻机库

## 背景与目标

- 会话-6，分支 `codex/pro-art-rebuild`，基线 `660a9ca`。
- 用户要求战机适当增加科幻感与多边形细节，停机仓同时增加科幻设施与精细程度。
- 延续写实军工方向，以及上一轮固定机位、机首朝舱外和统一 3D 场景的成果。

## 约束与原则

- 六架玩家机、四类敌机统一升级；源模型、GLB、斜视预览和俯视降级图保持一致。
- 保留 600×800 逻辑坐标、碰撞、数值、60 Hz 固定时间步和侧倾规则。
- 优先可辨识的结构细节，不单纯细分大平面；新增几何按材质合批。
- 机库机械细节只属于展示场景，静止时不持续绘制。

## 关键实现说明

- 喷口采用真实中空截面和 18 片外部瓣片，原授权机械组件放置在内腔之前，避免旧栅片堵住新涡轮。
- 前掠翼有凹角，翼面分区使用 Blender 的多边形三角划分，避免简单三角扇跨出翼面形成悬空片；预览同时检查斜视轮廓和透明边界。
- 飞机默认机首仍指向 -Z 舱口；展示相机与模型加载无关，不引入额外占位飞机或加载机位。
- 十种战机均为 9 个材质批次，保留 2/4 个 `exhaust_*` 挂点；材质及几何仍由 `modelLibrary` 共享。
- 展示后期处理不进入 `battleScene`。GTAOPass 当前版本未在 `dispose` 覆盖的两个材质由展示组件补充释放。
- 新增设施均为原创程序几何，不新增外部授权素材。

## 关键风险

- 模型面数和下载体积增加，需要核对持续战斗帧率。
- 展示增加环境遮蔽与合成缓冲区，高分屏拖动成本增加，需要实际采样。
- 机库与战斗共用模型缓存，展示材料必须保持克隆后修改，避免污染战斗材质。
- Safari 与实体移动设备尚未验证。

## 测试用例

### TC-001 十类模型与配套预览

- 类型：资产/视觉检查；优先级：高。
- 操作：逐类读取 GLB、统计面数/材质/挂点；查看斜视与后侧模型，核对轮廓、封闭座舱、喷口深度、预览完整性。
- 预期：十类均加载成功、保持挂点、无翼尖裁切、不同视图来自同一源文件。
- 状态：通过；十类均保持 9 个材质批次和正确挂点。20 张预览/俯视图的透明边界均未碰到图片边缘。

### TC-002 冷启动、切机与高分屏

- 类型：浏览器回归；优先级：高。
- 操作：`npm run qa:parking`，延迟十份 GLB，切换不同视口/DPR，逐类切换及拖动旋转。
- 预期：加载前后背景机位和按钮文字不变；复用画布；无溢出；起落架接地且战机完整入镜。
- 状态：通过；18 组画布尺寸、10 类切机、280 组真实顶点投影取景，控制台无错误。

### TC-003 战斗与降级

- 类型：功能/性能回归；优先级：高。
- 操作：`npm run qa:browser`，检查射击、切机、侧倾、回正、暂停、结算和禁用 WebGL 的 Canvas 2D 降级。
- 预期：原行为保持，1440×900 Chrome 持续战斗接近 60 FPS。
- 状态：通过，10 秒战斗采样 60 FPS，射击、结算、侧倾与降级均正常。

### TC-004 类型与生产构建

- 操作：`npx tsc --noEmit`、`npm run build`、`git diff --check`。
- 状态：通过。Vite 仍提示大体积主包，未出现构建错误。

### TC-005 高分屏持续检视

- 操作：1440×900、DPR 2，连续拖动 6 秒，观察后期处理负载及控制台。
- 状态：通过；1440×900、DPR 2，6 秒连续旋转采样 60 FPS，P95 帧间隔 16.7 ms，未出现超过 33.4 ms 的帧；控制台无错误。
