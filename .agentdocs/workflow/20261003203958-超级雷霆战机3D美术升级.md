# 超级雷霆战机 3D 美术升级

## 背景与目标

- 在写实科幻界面的基础上，交付十类独立 3D 战机、3D 战斗场景和横移侧倾。
- 保持“超级雷霆战机”及五种语言译名、原有玩法数值、碰撞范围和固定时间步。
- 桌面浏览器优先；保留 WebGL 不可用时的 Canvas 2D 画面。

## 约束与决策

- 基于 `codex/realistic-space-war` 创建开发分支 `codex/super-thunder-3d`，保留该分支已有的写实界面与帧率修复。
- React、TypeScript、Vite 保持不变，战斗画面新增 Three.js WebGL 2 正交场景；逻辑仍为 600×800 和 60 Hz。
- 以 Quaternius Ultimate Spaceships Pack 的 CC0 模型为基础，分别加工六架玩家战机和四类敌机；授权与对应关系见 `assets/model-sources/README.md`。
- 为避免跨机型通用零件悬空，新增面板使用原机身网格射线定位；最终 `.blend` 保存可编辑源文件，GLB 用于运行，PNG 由同一源文件渲染给界面使用。
- 移动侧倾根据实际水平位移速度计算，约 ±30°，停止横移后指数平滑回正；不改变碰撞。

## 代码与资源变更

- `render/battleScene.ts`：模型加载与复用、正交相机、场景光照、分层星空、弹体和粒子实例化、侧倾、GPU 资源释放。
- `render/modelManifest.ts`：十类 GLB 和预览图的统一映射。
- `game/engine.ts`：记录每个固定步的玩家实际位移，供侧倾读取，不改变移动结果。
- `App.tsx`：优先启用 Three.js，失败时沿用 Canvas 2D；游戏规则和界面状态继续由 React 管理。
- `components/`、`index.css`、`index.html`、`public/favicon.svg`：统一展示模型预览、适配 1440×900 完整战场并补充品牌元数据。
- `scripts/build_models.py`、`scripts/render_previews.py`：可重复的模型加工与预览流程。
- `assets/model-sources/`、`public/assets/models/`、`public/assets/previews/`：十类可编辑模型、运行资产和界面预览。
- `scripts/qa_browser.mjs`：桌面 Chrome 冒烟验收与 10 秒帧率采样。

## 风险与验证

- 部分机型原始轮廓较细长；显示尺寸独立于碰撞体，调整视觉比例时需检查重叠感和子弹可读性。
- GLB 使用 WebP 贴图，需在目标浏览器检查材质显示；加载失败时以简化 3D 机体代替单个模型。
- 首次首页渲染可能早于模型加载，因此模型加载完成后需要重建已显示的占位机体。
- 类型检查：`npx tsc --noEmit`。
- 构建：`npm run build`。
- 浏览器：`npm run qa:browser`，检查十类模型请求、五语言标题、首页/机库/情报/设置、移动、射击、暂停恢复与 1440×900 帧率；截图保存在系统临时目录。
- 实测结果：十个 GLB 均返回 200；机库六张、情报四张预览均加载；五种标题匹配；暂停与恢复、渲染切机、射击和死亡结算状态通过。持续战斗 10 秒为 60 FPS（本机 Chrome 无头模式、1440×900）。模拟右移、左移后侧倾分别为约 -18°、+18°，停止后约 0.1°；禁用 WebGL 的 Chrome 可进入 Canvas 2D 战斗。类型检查、生产构建和 `git diff --check` 通过。构建仅有大于 500 kB 的单块体积提示。
- 未单独进行移动端设备的性能采样；本次验收以桌面 Chrome 为准。

## 测试用例

### TC-001 资源与材质

1. 打开首页、机库与情报页，检查六架玩家机和四类敌机均有预览。
2. 开始战斗，确认十类 GLB 请求成功，机首方向、阵营颜色和材质正常。

预期：模型均可加载，预览与战斗使用同源资产。

### TC-002 侧倾与回正

1. 在战场中短按右移，再松开；用左移和触控横拖重复。
2. 检查约 30° 的侧倾、松开后的回正和位置不跳变。

预期：侧倾只影响模型朝向，碰撞范围和速度不变。

### TC-003 性能与兼容

1. 以 1440×900 在 Chrome 持续战斗 10 秒，记录动画帧率。
2. 禁用 WebGL 2 后重新加载。

预期：正常环境接近 60 FPS；WebGL 不可用时出现 Canvas 2D 画面。
