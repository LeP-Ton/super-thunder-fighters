# 统一 3D 机库与冷启动取景

## 背景与目标

- 会话：会话-5；分支：`codex/pro-art-rebuild`，基于会话-4 的 `eecabfc`。
- 用户指出：“机库准备中”期间的飞机与加载完成后位置不同；正式首页仍有透视失真，希望机头朝舱外，必要时将机库建模。
- 本次采用完整实时 3D 舱室，让战机、地板、结构梁、舱门、阴影与反射使用同一世界坐标和相机。

## 原因与决策

- 原按钮以 `visualsReady` 为条件等待十架战斗模型，未就绪时将文案改为“机库准备中”。这不是首页独立加载流程。
- 原 `ShipShowcase` 在 GLB 加载前显示 Blender 输出的缩略图，随后切换至实时模型；两者相机和机位不同，造成跳变。
- 叠图的机库背景与单独渲染的战机没有共同的三维地面、光源和舱口，微调 CSS 无法保证严格透视一致。
- 改为先呈现正式 3D 机库，模型到达后原位添加；按钮始终使用“开始任务”及相应译文，战斗资源就绪前仍保留必要的禁用保护。
- 相机只依赖容器尺寸；不根据模型加载、选中机型或旋转重新缩放。
- 模型加载与场景生命周期分离，切机保留同一个 WebGL 画布。新机型到达前保留当前机体，避免再次进入占位图。

## 范围与约束

- 地面 y=0，舱门位于 -Z；默认机首朝 -Z，镜头从机尾上方看向舱外。
- 六类玩家战机、四类敌机以及三个展示页面统一使用新机库。
- 保持战斗逻辑、数值、碰撞、固定时间步和源 GLB 不变。
- 展示中降低热喷口发光时克隆对应材质，避免影响共享战斗模型。
- 静态预览仅用于 WebGL 不可用或模型失败；正常冷启动不显示静态占位机体。

## 关键实现说明

- 相机参数不读取模型边界，冷启动空机位和最终模型保持相同构图。
- 机库结构与地板采用真实几何；程序纹理仅承担金属接缝与磨损，不再用照片模拟地面透视。
- 反射贴图固定为 768×768，混合强度 14%；场景静止时不重复提交绘制，变化时才更新反射与画面。
- 环境结构组件按材质与投影属性合批，避免数百个独立绘制调用。
- 舱外行星复用现有自有海洋资源，无新增外部图片或模型许可。

## 验证

### TC-001 冷启动一致性

- 类型：浏览器回归；优先级：高。
- 操作：拦截十个 GLB 下载请求，等待正式环境先渲染；保存加载截图，再放行模型。
- 预期：不出现占位机体，背景相机不移动，按钮文案不替换，模型就绪后允许开始。
- 结果：通过。加载前后左上背景区域 PNG 完全一致，静态占位图片数量为 0，按钮文案一致。

### TC-002 尺寸与机型切换

- 类型：布局/交互回归；优先级：高。
- 操作：覆盖 DPR 1、1.25、1.75、2、3，1511×818、1920×1080、1280×720、768×1024、390×844；依次选择十类战机并拖动。
- 预期：CSS 画布尺寸等于容器；像素密度只影响缓冲区；无横向溢出；切机复用同一 Canvas。
- 结果：18 组尺寸检查与十类机型切换通过，两个检视页拖动成功，Chrome 无错误。

### TC-003 取景与接地

- 类型：几何回归；优先级：高。
- 操作：遍历全部真实机体与起落架顶点，覆盖 7 种首页/检视尺寸、4 种朝向、10 类机型，共 280 组。
- 预期：轮胎接地误差小于 0.002；所有顶点在相机裁剪范围内，二维投影距画面边缘至少保留 4% 的 NDC 余量。
- 结果：通过；窄比例检视区已增加固定相机距离。

### TC-004 工程与游戏回归

- `npx tsc --noEmit`：通过。
- `npm run build`：通过；保留既有的 JS 大包提示，约 964 KB（gzip 269 KB）。
- `git diff --check`：通过。
- `npm run qa:browser`：通过。1440×900 Chrome 战斗采样 60 FPS；射击、切机、侧倾、回正、暂停/恢复、结算、多语言标题、编队操作与 WebGL 关闭后的 Canvas 2D 战斗均通过，浏览器错误为 0。

### TC-005 检视性能与首页降级

- 1440×900、DPR 2 的 Chrome 中持续旋转检视 6 秒，采样 60 FPS；包含阴影与 768×768 地面反射。
- 禁用 WebGL 后确认首页静态预览仍显示；专用尺寸约束防止全屏画布布局把降级缩略图放得过大。
- 性能记录见 `inspection-performance.json`；本机采样不能代表所有真实移动设备。
