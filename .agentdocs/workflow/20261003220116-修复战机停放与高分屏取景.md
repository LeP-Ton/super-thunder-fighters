# 修复战机停放与高分屏取景

## 背景与目标

- 会话：会话-4。
- 分支：`codex/pro-art-rebuild`；基于会话-3 的 `ca45f60`，未发生分支切换。
- 用户截图中：首页、情报页战机放大并偏到右下角，机体被裁切；要求放回机库地面。
- 使用现有机库背景，叠加真实 3D 起落架、机位标线与接地阴影，校正展示位置和取景。

## 根因与决策

- `renderer.setSize(width, height, false)` 只更新像素缓冲区。原有样式作用于父容器，子 Canvas 没有显式 CSS 尺寸，Retina 设备将放大后的缓冲区尺寸用作页面显示尺寸。
- Chrome 在 1511×818、DPR 2 下复现：旧容器为 1194×509，Canvas 实际显示为 2088×891，与用户截图的裁切一致。
- 上轮浏览器脚本只覆盖 DPR 1，没有发现此问题。本轮新增连续 DPR 切换和多个分辨率的针对性回归。
- 显式固定 Canvas CSS 宽高为容器的 100%；像素缓冲区独立采用最大 1.75 的 DPR。
- 取景基于机体真实凸包轮廓。包围球/包围盒包含过多空白，导致修复裁切后机体过小。
- 固定机库相机方向；拖动检视仅绕竖直轴旋转机体，避免环绕相机与静态背景产生透视冲突。

## 约束与范围

- 保持原 GLB、战斗渲染、运动规则、碰撞与数值不变。
- 起落架、地面机位标线是展示附加物，不写入战斗模型或源资产。
- 保留现有机库背景图，未将整个机库制作成 3D 场景。
- 沿用共享模型缓存；释放视图自建的几何、材质、环境和阴影资源，不释放共享模型资源。

## 验证结果

### TC-001 高分屏及跨屏尺寸

- 类型：浏览器布局回归；优先级：高。
- 操作：在同一页面依次切换 1511×818 的 DPR 1、1.25、1.75、2，再测试 1920×1080@2、1280×720@2、390×844@3。
- 断言：Canvas CSS 宽高等于容器，缓冲区匹配受限 DPR，页面无横向溢出。
- 结果：通过；含机库/情报共 17 组尺寸检查。

### TC-002 十类模型停放与旋转边界

- 类型：几何回归；优先级：高。
- 操作：十类模型各测试 3 种纵横比、4 个朝向，共 120 组。
- 断言：独立遍历全部模型和起落架顶点，投影均在可视范围内，深度未超出相机裁剪面；轮胎底部与地面差小于 0.002。
- 结果：通过；验证数据见 `../artifacts/20261003-hangar-parking/verification.json`。

### TC-003 页面切机与拖动

- 类型：浏览器交互回归；优先级：高。
- 操作：依次选择六架玩家战机与四类敌机；在机库和情报页拖动检视。
- 断言：所有模型进入 ready 状态；拖动前后画布发生变化；无浏览器错误。
- 结果：通过；已人工查看首页、情报、拖动后画面和手机截图。

### TC-004 工程检查

- `npx tsc --noEmit`：通过。
- `npm run build`：通过；保留既有的大体积 JS 分包提示。
- `git diff --check`：通过。

## 关键风险与未验证项

- 机库为固定背景，适合当前固定相机的停放展示；未来若增加自由漫游，需要将环境纳入同一 3D 场景。
- 未在 Safari 或真实手机硬件上验证；本轮手机验证为 Chrome 的 390×844、DPR 3 视口。
- 本轮未重跑完整战斗性能测试；战斗代码与 GLB 没有变更。
